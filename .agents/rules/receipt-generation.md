# receipt-generation.md

> 🔴 All rules here are hard requirements from PRD §6.9, §D1, §E1, and §L1.

---

## Rule 1 — Two Types of Receipt; Two Different Mechanisms

| Receipt type | Generated by | Stored | User action |
|---|---|---|---|
| Manual cash payment | `react-to-print` in browser | Not stored as PDF | Bursar prints directly from browser |
| Online payment | Puppeteer on worker server | PDF in Cloudinary/S3 with signed URL | Parent downloads from payment history |

🔴 **Never use Puppeteer to generate cash receipt PDFs.**  
🔴 **Never use `react-to-print` for online payment receipts.**

---

## Rule 2 — Puppeteer Runs on the Worker Server Only

🔴 **Puppeteer and `@sparticuz/chromium` are imported only inside `worker/`.**  
They must never appear in any file under `src/`. Vercel serverless functions cannot run Puppeteer. A deployment that includes Puppeteer in `src/` will pass CI and fail in production on the first receipt request.

See `folder-structure.md` for the ESLint rule that enforces this boundary.

---

## Rule 3 — The "Generating" UI State

🔴 **When `Receipt.fileUrl` is `null`, the parent's payment history shows:**  
_"Receipt generating — check back in a moment"_  
with an auto-refresh every 15 seconds.

🔴 **Once `fileUrl` is populated, the download link appears automatically** (via the 15-second poll or a page refresh).

🔴 **Never show a broken download link when `fileUrl` is null.**  
The download button must not appear until `fileUrl` is a valid URL.

_(PRD §E1-AC8)_

---

## Rule 4 — Receipt Layout Specification

🔴 **All receipts (both cash print and online PDF) follow this A5 portrait layout exactly:**

- **Size:** A5 portrait — 148mm × 210mm
- **Header zone (top 30mm):** school logo (left, max 40mm wide), school name in bold 14pt, school address in 9pt, school phone in 9pt.
- **Divider:** 1pt horizontal rule.
- **Receipt title:** "OFFICIAL PAYMENT RECEIPT" centred, 12pt bold.
- **Receipt metadata (2-column table):** Receipt No | `RCP-YYYY-NNNNNN`, Date | `DD/MM/YYYY`, Payment Method | Cash / Card / Bank Transfer / USSD.
- **Student details (2-column table):** Student Name, Admission No, Class.
- **Payment details table:** Description | Amount (NGN). One row per fee line item if known, or a single row "School Fees Payment." Total row in bold.
- **Footer zone:** "Recorded by: [Bursar Full Name]", QR code (right-aligned, 20mm × 20mm) encoding the receipt verification URL, "This is an official receipt. Keep for your records." in 8pt italic.
- **Online payment receipts additionally show:** the Flutterwave transaction reference number.

🔴 **The school logo, name, address, and phone are always read from `school.config.ts`. Never hard-coded.**

---

## Rule 5 — QR Code on Every Receipt

🔴 **Every receipt (cash and online) includes a QR code that encodes exactly:**  
`https://[SCHOOL_DOMAIN]/verify/receipt/[receiptNumber]`

The QR code is positioned right-aligned in the footer zone, 20mm × 20mm.

This allows any party (parent, auditor, third party) to verify that a receipt is genuine without logging in. _(PRD §D1-AC7, §L1)_

---

## Rule 6 — Public Receipt Verification Endpoint

🔴 **`GET /verify/receipt/[receiptNumber]` is a public, unauthenticated endpoint.**  
No authentication required. No session check. No RBAC check.

🔴 **The endpoint returns only:**
- Student first name (not last name)
- Amount paid
- Date of payment
- School name
- Payment method

🔴 **The endpoint must not return:**
- Student last name
- Admission number
- Class
- Email
- Phone
- Any other PII

🔴 **On an invalid receipt number:** return HTTP 404 with the message:  
_"Receipt not found. If you believe this is an error, contact the school."_

_(PRD §L1)_

---

## Rule 7 — Receipt PDF Performance Target

🔴 **Receipt PDFs must be available within 60 seconds of payment completion under normal load.**  
The `generate-receipt-pdf` BullMQ job has 2 retries. On final failure:
1. `Receipt.fileUrl` remains `null`.
2. Log the error.
3. The parent continues to see the "generating" state.
4. Log a Sentry error for investigation.

_(PRD §6.5, §E1-AC8)_

---

## Rule 8 — Signed URL Expiry

🔴 **Receipt PDF files stored in Cloudinary or S3 are served via signed URLs that expire after 1 hour.**  
The signed URL is generated on demand when the parent or bursar requests the download. Never expose a permanent public URL for a receipt file. _(PRD §6.6)_

---

## Rule 9 — Bursar Can Reprint Any Receipt

🔴 **The bursar can reprint any cash receipt at any time from the student's payment history.**  
The `react-to-print` receipt view must accept a `receiptId` prop and render the correct receipt data for that ID.
