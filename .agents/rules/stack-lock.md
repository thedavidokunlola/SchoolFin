# stack-lock.md

> 🔴 No locked choice may be replaced, swapped, or supplemented with an alternative without explicit written sign-off from the project owner.  
> Security patch version bumps on locked libraries are permitted and do not require sign-off.  
> "Supplemented" means adding a second library that does the same job as a locked one. Also forbidden.

## What "Locked" Means in Practice

### Permitted without sign-off
- Bumping a locked library to a newer **patch or minor version** (e.g., `4.2.1` → `4.2.3` for a security fix).
- Adding a utility library that does something no locked library does (e.g., a date formatting helper, a slug generator).
- Adding a dev-only tool (e.g., a new ESLint plugin, a test helper).

### Requires explicit written sign-off
- Replacing a locked library with a different library that does the same job.
- Adding a second library that duplicates the role of a locked library (e.g., adding `nodemailer` alongside Resend).
- Bumping a locked library to a new **major version** (e.g., `4.x` → `5.0`) — major versions often contain breaking changes.
- Changing the hosting platform for any tier.

### Always forbidden
- Importing the Flutterwave SDK outside `src/server/services/payment-gateway/`.
- Using any SMS provider other than Termii.
- Using any email provider other than Resend.
- Running Puppeteer anywhere other than the worker process on Railway/Render.
- Using `Float` or JavaScript `number` for monetary amounts.

## If a Locked Tool Has a Problem

Do not substitute. Instead:

1. Document the problem clearly (version, error, CVE reference if applicable).
2. Apply the security patch if one exists.
3. If no patch exists and the problem blocks the task, stop and report to the project owner with a specific recommendation.
4. Wait for written sign-off before proceeding with any swap.

The agent must never make a substitution and continue, then mention it at the end of the task.
