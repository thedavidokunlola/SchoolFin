# prisma-schema.md

> 🔴 The schema in PRD §9 is the authoritative data model.  
> Breaking any rule in this file means the task failed, even if the feature appears to work.

---

## The Schema Is Locked

🔴 **Do not rename any model, field, enum value, or index.**  
Prisma generates types from the schema. A rename breaks all downstream TypeScript. A renamed field in a migration drops the old column and creates a new one — data is lost in production.

🔴 **Do not change any field's type.**  
Specifically: `Decimal` fields must remain `Decimal @db.Decimal(12,2)`. They must never become `Float`, `Int`, or `String`. See `money-handling.md`.

🔴 **Do not remove any `@@index` directive.**  
Indexes exist to meet the performance requirements in PRD §10. Removing one silently degrades query performance under load.

🔴 **Do not add new models or fields without an explicit instruction.**  
An "explicit instruction" means a task description or human message that: (a) names the model or field, (b) states its type, and (c) states its purpose. An implicit need ("I think I need a status field here") is not an explicit instruction — stop and ask.

🔴 **Do not hand-edit migration files.**  
Migrations are generated by `prisma migrate dev`. If a generated migration is wrong, fix the schema and regenerate. Never edit the SQL in a migration file directly.

---

## Monetary Fields

🔴 Every field that holds a monetary amount uses exactly:
```prisma
fieldName Decimal @db.Decimal(12, 2)
```
No exceptions. See `money-handling.md` for the full rule.

---

## Soft Deletes Only

🔴 **No hard deletes for any user-visible entity.**  
Deactivation is always `isActive = false` (or the model's equivalent flag). The following models use soft delete:

| Model | Soft delete field |
|---|---|
| `User` | `isActive` |
| `Student` | `isActive` |
| `FeeStructure` | `isActive` |
| `InstallmentPlan` | `isActive` |
| `ParentStudentLink` | `isActive` |
| `DebtCollectionRule` | `isActive` |
| `CommunicationTemplate` | `isActive` |

🔴 **Never issue a `DELETE` statement against any of the models above.**  
`prisma.user.delete(…)` is forbidden. Use `prisma.user.update({ data: { isActive: false } })`.

---

## AuditLog Is Immutable

🔴 **The database service account has `INSERT` and `SELECT` on `AuditLog` only.**  
`UPDATE` and `DELETE` are not granted at the database level.

🔴 **There is no application-layer code that calls `prisma.auditLog.update(…)` or `prisma.auditLog.delete(…)`.**  
If you need to indicate that something was reversed, write a new `AuditLog` record with a `REVERSAL` action. Never modify the original.

---

## The `creditBalance` Field

🔴 `Student.creditBalance` is the only balance-adjacent field on the `Student` model.  
Do not add a `cachedBalance`, `outstandingBalance`, `totalPaid`, or any other derived financial field to `Student`. The outstanding balance is always computed dynamically by `computeOutstandingBalance`. _(PRD §B1)_

---

## The `cardToken` Field

🔴 `Installment.cardToken` stores an AES-256 encrypted Flutterwave card token, or `null`.  
It never stores a raw card token, a card number, a CVV, or any other raw card data. The encryption happens in `src/server/services/encryption/` before the Prisma write.

---

## FeePosting Reversals

🔴 Reversals do not modify existing `FeePosting` records.  
A reversal creates a new `FeePosting` record with `type = REVERSAL`. The original record with `type = CHARGE` is never touched. The balance formula handles both types. _(PRD §C2-AC8)_

---

## ParentStudentLink Unlinking

🔴 Unlinking a student from a parent sets `ParentStudentLink.isActive = false`.  
It does not delete the `ParentStudentLink` record. The audit log records who removed the link and when. _(PRD §A4)_

---

## Prisma Client Usage

🔴 The Prisma client is instantiated once in `src/server/db/prisma.ts`.  
Never call `new PrismaClient()` anywhere else. Import the singleton.

🔴 Always use Prisma's `select` or `include` to fetch only the fields needed.  
Never call `prisma.student.findMany()` with no `select` and then filter in JavaScript — this loads full rows for all students and breaks performance at scale.

## Migrations Checklist

Before running `prisma migrate dev`:
- [ ] Schema change was explicitly instructed (named model, named field, stated type and purpose)
- [ ] No monetary field changed from `Decimal`
- [ ] No `@@index` was removed
- [ ] No model was renamed (check all downstream TypeScript imports)
- [ ] Migration reviewed — no destructive `DROP COLUMN` unless the field truly no longer exists in the PRD
